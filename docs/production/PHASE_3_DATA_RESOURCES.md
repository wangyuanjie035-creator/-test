# 阶段 3：配置数据化

日期：2026-07-31—2026-08-05  
状态：已完成  
原则：迁移配置所有权，不改变效果执行逻辑、候选顺序、数值或黄金 Seed。

## 数据边界

| 配置 | Resource | 运行时职责 |
|---|---|---|
| 卡牌 | `LabCardDefinition` | ID、名称、说明、槽位、效果类型、两级分数、自动化标记、构筑标签 |
| 卡池 | `LabContentCatalog` | 加载显式资源清单、建立 ID 索引、拒绝无效配置 |
| 音效 | `LabAudioCueDefinition` | Cue ID、音高序列、时长、振幅、播放音量、重要事件标记 |

Resource 只保存只读定义，不访问场景树，也不保存局内状态。模拟行为继续留在 `LabSimulation`，避免把规则拆进大量资源脚本。

## 迁移顺序

1. 将 12 张卡牌迁入独立 `.tres`，并把玩家可见说明从工作台移入卡牌定义。
2. 增加目录级配置校验：空 ID、重复 ID、非法槽位、非法效果、缺名称/说明、分数越界、空标签均直接失败。
3. 用构筑标签替代候选测试和后续构筑分析中的分散 ID 清单，但暂不改变候选算法。
4. 将五类合成音效参数迁入独立 `.tres`，音频节点只负责生成、缓存和播放。
5. 全部统一门禁通过，固定 Seed `240731` 黄金结果保持不变。

## 兼容约束

- 保留现有卡牌 ID、枚举序号、槽位和分数，避免黄金路线漂移。
- 采用显式资源清单，不依赖运行时目录遍历，确保导出包和测试加载顺序稳定。
- 共享 Resource 只读使用；局内等级、安装天数和实例 ID 仍由 `LabRunState` 保存。
- `LabContentCatalog` 返回的定义是进程级共享只读对象；运行时禁止修改卡牌字段或标签。
- 配置错误必须在启动/门禁阶段暴露，不能在第 8 天才因缺字段崩溃。

## 验收门槛

- 新卡主要通过新增 `.tres` 和加入目录清单完成。
- 工作台不再保存卡牌说明字典。
- 重复 ID、空 ID、非法槽位/效果、缺字段和非法分数均有自动测试。
- 构筑标签可由测试和后续平衡工具读取。
- 音效参数不再硬编码在 `LabAudioFeedback._ready()`。
- compile / unit / golden / scene-smoke 全部通过。
