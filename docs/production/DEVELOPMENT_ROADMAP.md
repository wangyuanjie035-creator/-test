## 玩法阶段的量化验收

- 新手理解：75% 首次玩家无需口头指导完成第 1 天；80% 能解释生产链、超频与技术债。
- 正反馈：80% 能指出当天最大产出来自哪里；70% 主动提到至少一次爽点；单日播放不超过 8 秒。
- 构筑差异：三条路线各有至少 20% 主动选择率；玩家能描述各自优势与风险。
- 平衡目标：新手胜率 30%–50%，熟练玩家 55%–70%；任一卡首见必选率不超过 70%。
- 决策有效性：跳过与不超频分别占至少 15% 的有效决策；不存在多数 Seed 通用的固定前四日脚本。
- 重玩性：60% 愿意立即再开一局；四局内至少采用两种核心构筑；75% 失败后知道下局要改什么。

## 每周固定节奏

- 周一：锁定一个可验证假设和唯一周目标。
- 周二至周三：实现最小改动；新想法只进入待办。
- 周四：盲测或固定 Seed 验证，开发者不在旁边解释。
- 周五：自动测试、两局人工回归、复盘并更新 GDD/日程。纯测试/结构阶段且无玩法行为变化时，可用一局固定 Seed 加一局随机 Seed；任何玩法、数值或结算变更仍必须使用两个不同随机 Seed。
- 每两周必须生成一个可独立试玩版本。
- 每周至少预留 20% 时间处理 Bug、结构清理和测试。

## Agent 监察协议

只有主开发 Agent 可以修改当前阶段核心文件。其余 Agent 默认只读，避免共享工作区互相覆盖。

1. **主开发 Agent**：实现当前阶段、运行测试并提交验收证据。
2. **制作人监察 Agent**：检查时间盒、范围膨胀和砍功能顺序。
3. **玩法监察 Agent**：检查决策质量、构筑差异、试玩样本和正反馈指标。
4. **技术监察 Agent**：检查 Godot 生命周期、模块边界、测试、Tween、音频、存档和导出风险。
5. **系统游戏设计师 Agent**：检查核心循环、循环杠杆、风险回报、预期—行动—反馈、构筑心理承诺和失败后的再尝试动机；对“技术可行但没有制造新决策”的玩法拥有否决权。
6. **策略玩家体验师 Agent**：以资深牌组构筑、Roguelike 与系统策略玩家视角寻找必选、固定解、伪选择和信息不对称；默认只读，不用个人偏好替代反事实证据。
7. **可理解性玩家体验师 Agent**：以广泛 3A 与独立游戏经验检查首次上手、按钮语义、情绪曲线、成功/失败归因和正反馈；默认只读，反馈必须附可观察指标。

玩家体验师采用轮换制；同一功能至少由两种不同玩家视角独立评价。Agent 试玩用于尽早发现问题和设计测试，不计入阶段 8 的真实外部玩家样本，也不能代替用户亲自试玩。

### Agent 自主试玩闭环

1. **模拟器体验师**批量运行不同 Seed，并在关键日建立同状态反事实分叉，寻找固定解、必选牌和无效选项。
2. **界面体验师**通过 Godot 运行时实际点击候选、超频与结算，记录首次理解、误点、决策时间、截图和反馈强度。
3. **系统设计师**只读汇总证据，给出 `通过 / 有条件通过 / 否决`，并限定最小修正范围。
4. **主开发 Agent**实现最小修正，运行 compile / unit / golden / scene-smoke 门禁。
5. 使用未参与调参的新 Seed 和另一名体验师复测；未通过则重复闭环，禁止在同轮扩展新系统。

以下情况才请求用户决断：改变核心心理承诺、扩大阶段范围、需要删除已确认玩法、两种方案证据接近，或连续两轮优化仍被否决。普通数值、提示、反馈和明确缺陷由 Agent 闭环直接处理。

阶段结束时，制作人、玩法/系统设计师和技术监察必须先独立给出：`通过 / 有条件通过 / 返工`。主 Agent 汇总后才能更新阶段状态。监察对话不能替代真实玩家试玩。

阶段 4 起，每项玩法改动在实现前必须回答四个问题：玩家这一回合新增了什么判断；玩家主动拉动了哪个循环杠杆；成功时哪条因果链会被明确放大；失败时玩家能否说出下一局要改什么。任一项没有具体答案，改动只进入备选清单，不进入实现。

## 固定技术门禁

每阶段结束必须全部满足：

1. Godot 编译无新增错误。
2. `validate_lab_engine.gd` 与新增测试全部通过。
3. 固定 Seed 可复现，并完成人工双局回归；玩法、数值或结算变更阶段必须至少跑两个不同随机 Seed，纯测试/结构阶段可采用固定 Seed与随机 Seed各一局。
4. 无孤儿节点、残留 Tween、重叠音频或输入锁。
5. 1280×720 与 1920×1080 截图检查通过。
6. 更新 GDD、数值变更和不做事项。
7. 至少一名非实现 Agent 完成独立审查。

## 硬性止损规则

- 某阶段连续两轮未达标：停止新增内容，回退到最近通过版本。
- 新功能不能用一句话说明它制造了什么新决策：不做。
- 新卡只提高产量、不改变取舍：合并为升级或删除。
- 玩家同时“不懂”和“不爽”：先解决不懂。
- 构筑差异未通过前，冻结地图、Boss、剧情、商店、局外成长和大卡池。
- Alpha 后内容冻结，只允许修复、平衡和替换表现。

## 延期时砍功能顺序

1. 剧情分支、角色对话和复杂世界观展示。
2. 局外成长树、货币与永久属性。
3. 第四条及之后的构筑路线。
4. 大量随机事件、稀有卡和高级粒子。
5. 成就、排行榜与每日挑战。
6. 手柄、多语言和非首发平台。

不可砍：存档安全、设置、可读性、核心音效、错误处理、自动测试和干净导出。

## 正式版本远期预期

垂直切片通过后，再安排约 8–12 周用于内容纵切片、正式美术音频、更多外部试玩和发布准备。  
全职个人开发者的小型正式版本现实周期约 4–5 个月；业余开发约 7–10 个月。发布前另保留至少 2 周纯缓冲，不用于增加系统。
