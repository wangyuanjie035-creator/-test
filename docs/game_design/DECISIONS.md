# 决策记录

本文档记录已经做出的关键取舍。每条决策后续可以被新决策替代，但不要直接删除旧记录。

## D-001：使用 Godot 作为实现引擎

状态：已采用。

原因：

- 当前工作区已经是 Godot 项目。
- 项目配置显示 Godot 4.5 系列特性。
- 适合 2D 像素风、UI、资源化数据和桌面发布。

影响：

- 后续原型优先采用 Godot 场景、脚本和 Resource 数据结构。
- 文档中仍可讨论纸面规则，但实现规格要落到 Godot 模块。

## D-002：核心类型为 Roguelite 卡牌构筑

状态：已采用。

原因：

- 研究生过程天然适合随机事件、构筑、阶段考核和结局沉淀。
- 用户明确希望参考《杀戮尖塔》的构筑 BD 加回合制体验。

影响：

- 所有系统都要服务于“单局构筑”和“局外成长”。
- 研究生主题卡牌不是装饰，而是构筑来源。

## D-003：坏结局也提供正反馈

状态：已采用。

原因：

- 用户明确希望即使坏结局也获得资源或能力，然后再来一次。
- 这能降低挫败感，强化 Roguelite 循环。

影响：

- 每种失败都要设计对应履历资源或解锁。
- 结算界面需要突出“本局留下了什么”。

## D-004：美术方向为像素风

状态：暂定采用。

原因：

- 用户提出可以是像素风。
- 像素风适合校园、实验室、办公室和卡牌 UI 的轻量表达。

影响：

- UI 要避免过度写实。
- 角色、场景和图标可以先用占位像素资产，再逐步替换。

## D-005：MVP 先限制范围

状态：建议采用。

原因：

- 卡牌游戏内容容易膨胀。
- 先验证核心循环比堆内容更重要。

影响：

- 第一版先做少量导师、方向、卡牌、Boss 和结算。
- 博士线和延毕线可以先在文档中完整设计，原型中逐步开放。

## D-006：完整结局采用“毕业轴 × 去向轴”

状态：已采用。

原因：

- 学位结果和社会去向并不天然一致。
- “按期毕业但暂未就业”“延期毕业但获得大厂 Offer”“退学后创业”等组合更符合研究生题材的真实张力。
- 单轴好坏排序会把就业简化成毕业附属奖励，也会削弱中后期时间冲突。

影响：

- 毕业轴与去向轴独立判定，再引用代表课题或失败资产生成结局文本。
- 不新增可见的就业值或合作网络；去向读取声望、成果、构筑风格、合作结果和资产转化。
- 中后期的面试、实习、创业邀请和 Offer 有效期必须与研究行动竞争时间。

## D-007：阶段 2 结束后单独校准风险轮廓

状态：已采用。

原因：

- 隐藏过少会让调查退化为执行清单。
- 隐藏过多会让失败重新变成不可理解的随机惩罚。
- 仅修改界面文字不能证明玩家实际感受到探索未知。

影响：

- 立项页不直接展示确切风险槽数量和单一确定收益。
- 阶段 2 结束后使用固定 Seed 做信息层级对照测试。
- 未获得足够真人样本时结果标记为 `INCONCLUSIVE`，不得由 Agent 代替真人判定。
