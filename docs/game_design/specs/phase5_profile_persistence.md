# Phase 5：实验室档案持久化

## 范围

本阶段先建立实验室模式独立的轻量档案，不保存进行中的 8 天局面。当前持久化字段只有：

- `version`：档案结构版本。
- `tutorial_seen`：新手说明是否已经确认。
- `runs_started`：启动的实验室局数。
- `last_seed`：最近一次开局 Seed。

局内断点续玩暂不进入范围，避免直接序列化控制器、Resource 或场景节点。

## 文件与安全

- 主档：`user://lab_engine/profile.json`
- 临时文件：`profile.json.tmp`
- 上一代备份：`profile.json.bak`
- 玩家可写数据使用 JSON，不加载 `.tres/.res`。
- 保存时先完整写入并刷新临时文件，再把已验证的旧主档轮换为备份，最后以重命名提交新主档。这是单进程下的崩溃可恢复写入，不宣称跨平台严格耐断电事务。
- 主档损坏时读取备份，并在不覆盖好备份的前提下重建主档。
- 高于当前程序版本的主档会返回“不支持”，不得读取旧备份覆盖，也不得在本次运行写入默认值。

## 版本规则

当前版本为 v1。无 `version` 的 v0 档案按以下字段迁移：

- `help_seen` → `tutorial_seen`
- `launch_count` → `runs_started`
- `seed` → `last_seed`

高于当前版本或无法解析的档案不得猜测读取；主档失败后尝试备份，主档和备份都失败时使用默认值。

## 生命周期

- 工作台进入场景时读取档案。
- 每次新开一局更新局数与 Seed。
- 玩家关闭新手说明时保存 `tutorial_seen=true`；以后仍可通过右上角帮助按钮主动打开。
- 场景冒烟测试在节点进入树前关闭持久化，避免污染正式 `user://` 数据。

## 验收

- 正常保存、读取与字段归一化通过。
- 连续保存两代后破坏主档，能够读取上一代备份并报告恢复。
- 恢复写回后第二次读取直接命中主档；仅剩备份的崩溃窗口也可恢复。
- 损坏主档不能覆盖最后已知良好备份；未来版本主档保持字节不变。
- v0→v1 迁移通过。
- 测试路径及其 `.tmp/.bak` 在测试后全部删除。
- 场景冒烟测试验证正式档案在测试前后存在性与字节内容完全不变。
- 编译、11 个核心测试套件、黄金路线和场景冒烟测试通过。
