## 目标

让测试 UI 更容易读懂一局流程。玩家进入路线后，应该能看到自己在第几个节点、哪些节点已经完成、后面还有什么；处理事件后，也应该看到事件选择带来的实际变化，而不只是选项预览。

## 路线地图首版

首版使用一行文字路线条显示固定路线：

```text
路线：[当前]1 普通压力 -> [未]2 食堂偶遇大牛 -> [未]3 周会压力 -> [未]4 论文被拒 -> [未]5 设备排队 -> [未]6 截稿临近
```

状态标记：

- `[当前]`：当前所在节点。
- `[已]`：已经完成或处理过的节点。
- `[未]`：尚未进入的节点。

设计意图：

- 先用低成本文字路线条验证路线信息是否足够清楚。
- 后续地图界面可以复用同一套路线状态，不需要重做逻辑。
- 在路线分叉实现前，先把“局内旅程感”补起来。

## 事件反馈首版

事件选择后，UI 会显示实际结果，例如：

```text
事件已处理：食堂偶遇大牛。
结果：灵感 +1；数据 +1；牌组新增：精读文献。
请从下方选择下一节点。
```

结果文本来自选择前后的战斗状态快照对比，当前追踪：

- 精力、进度、防护。
- 灵感、数据、草稿、经费、声望。
- 经验教训、方法论笔记、论文碎片。
- 牌组新增卡牌。

结果说明：

- 路线条能正确显示当前、已完成和未进入状态。
- 进入事件节点、处理事件、选择下一节点时，路线条都会更新。
- 事件结果不再只展示预览文本，而是展示实际状态差异。
- 事件结果可以同时覆盖资源变化和新增卡牌。
